# chp2 연습문제 

## 퍼즐 가로

- 3 데이터모델: 복잡한 현실 세계의 데이터를 좀 더 쉽게 이해할 수 있도록 기술하는 개념적 도구
- 4 논리적설계: 개념적 모델링 결과인 개념적 구조를 DBMS가 이해할 수 있는 논리적 구조로 변환하는 과정
- 5 물리적설계: 디스크에 데이터가 저장될 수 있도록 논리적 구조를 물리적 구조로 변환하는 과정
- 6 트랜잭션: 하나의 논리적 기능을 수행하기 위한 작업 단위 
- 8 무결성: DB 설계 시 고려 사항 중 하나로, 저장된 데이터 값은 제약조건을 항상 만족해야 한다는 것

## 퍼즐 세로

- 1 개념적설계: 현실 세계에서 인식한 데이터를 추상화를 통해 개념 세계의 추상적 개념으로 표현하는 과정
- 2 데이터모델링: 현실 세계의 데이터를 DB에 표현하기 위한 모델을 만드는 과정
- 7 확장성: DB 설계 시 고려 사항 중 하나로, 운영에 영향을 주지 않고 새로운 데이터나 프로그램을 추가할 수 있어야 한다는 것

## 연습문제

01. ( ) 안에 알맞은 용어는? - 개체
현실 세계의 데이터는 사람의 오감으로 인지할 수 있는 실체로, 둘 이상의 특성으로 구성된 (________)로 표현된다.

02. ( ) 안에 알맞은 용어는? - 엔티
개념 세계의 데이터는 개체의 의미로부터 인식된 개념으로, 둘 이상의 속성으로 구성된 (________)으로 표현된다.

03. 현실 세계의 직장인이 속한 세계에 따라 구분되는 구성 요소를 5개 이상 작성하시오.
| 구분 | 구성 요소 |
| :--- | :--- |
| 현실 세계의 직장인 | 이름, 나이, 직급, 부서 |
| 회사라는 개념 세계의 직장인 | 사원 번호, 성명, 입사일 |
| 자동차 보험사라는 개념 세계의 직장인 | 설계사 번호, 실적, 자격등급 |
| 회사라는 개념 세계와 대응하는 컴퓨터 세계의 직장인 | VARCHAR(20), INT, DATE 등의 데이터 타입으로 정의된 레코드 |

04. 데이터 모델링의 각 단계와 설명을 바르게 연결하시오.
- 개념적 스키마 모델링 -> c
- 논리적 스키마 모델링 -> a
- 물리적 스키마 모델링 -> b
- a. 개념적 모델링 결과인 개념적 구조를 DBMS가 이해할 수 있는 논리적 구조, 즉 데이터 모델로 변환하는 과정
- b. 디스크에 데이터가 저장될 수 있도록 논리적 구조를 물리적 구조로 변환하는 과정
- c. 현실 세계에서 인식한 데이터를 추상화를 통해 개념 세계의 추상적 개념으로 표현하는 과정

05. 데이터 모델링을 개념적 모델링, 논리적 모델링, 물리적 모델링으로 구분해서 수행하는 이유를 설명하시오.
- 복잡한 현실 세계를 한 번에 컴퓨터 세계로 옮기는 것이 어렵기 때문입니다. 단계를 나눔으로써 독립성을 유지하고, 설계의 오류를 줄이며 관리의 효율성을 높이기 위해서입니다.
06. 개념적 구조, 즉 개념적 모델링 결과를 DBMS가 직접 이해할 수 없는 이유를 설명하시오.
- 개념적 구조(예: E-R 다이어그램)는 사람의 머릿속 개념을 표현한 추상적 모델인 반면, DBMS는 테이블, 트리, 그래프 같은 특정한 논리적 데이터 구조를 기반으로 동작하기 때문입니다.
07. 데이터 모델을 구성하는 세 가지 구성 요소를 쓰시오.
- 데이터 구조(Structure), 연산(Operation), 제약 조건(Constraint)
08. 개념적 데이터 모델의 구성 요소를 쓰시오.
- 개체(Entity), 속성(Attribute), 관계(Relationship)
09. 다음 중 데이터베이스를 구축하는 6단계를 바르게 나열한 것은? - c
- a. 요구 수집 및 분석 - DBMS 선정 - 개념적 설계 - 논리적 설계 - 물리적 설계 - 구현 및 테스트
- b. 요구 수집 및 분석 - DBMS 선정 - 논리적 설계 - 개념적 설계 - 물리적 설계 - 구현 및 테스트
- c. 요구 수집 및 분석 - 개념적 설계 - DBMS 선정 - 논리적 설계 - 물리적 설계 - 구현 및 테스트
- d. 요구 수집 및 분석 - 개념적 설계 - 논리적 설계 - DBMS 선정 - 물리적 설계 - 구현 및 테스트

10. 다음 중 DB 설계 전략에 대한 설명이 잘못된 것은? - c
- a. DB의 내용과 구조에 치중해서 설계하는 방법은 데이터 중심 설계다.
- b. 데이터의 처리와 응용에 치중해서 설계하는 방법은 처리 중심 설계다.
- c. 데이터 중심 설계와 처리 중심 설계 가운데 하나를 선택해서 진행하는 것이 효율적이다.
- d. 데이터 중심 설계와 처리 중심 설계들을 병행해서 진행하는 것이 효율적이다.

11. 다음 중 데이터베이스 설계 시 고려 사항에 대한 설명이 잘못된 것은? - b
- a. 보안: 불법적인 접근(데이터의 변경, 손실, 노출 등)에 대해서 DB를 보호할 수 있어야 한다.
- b. 확장성: 시스템 운영을 일시 중단하고 새로운 데이터나 응용 프로그램을 추가할 수 있어야 한다.
- c. 일관성: 저장된 데이터 값 간 또는 특정 질의에 대한 응답들 간에 상호 모순 없이 일치해야 한다.
- d. 무결성: DB에 저장된 데이터 값은 제약조건을 항상 만족해야 한다.
